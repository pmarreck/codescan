# Staged dependency parser interoperability

The shared `git-dependency-portability-gate` rejected an unchanged runtime Zig cache default in `flake.nix` as a dependency on `/.cache/zig`. Inspection of its `nix_tokens` function found that it ends an indented string at the first pair of single quotes, including the valid escaped shell interpolation prefix `''${`. It then interprets part of the shell string as a Nix path.

The rejection was reproduced by the actual pre-commit hook. The project uses an equivalent double-quoted Nix shell string now. The existing cache inheritance/default tests pass, and the real staged gate passes without an override. All five sandboxed release builds use the same declared source inputs; runtime cache defaults are not dependency sources.

The shared parser required regressions for escaped interpolation in indented strings, including nested quoting and ordinary runtime paths, while retaining rejection controls for actual host-local dependency declarations. The approved request was delivered through a durable inbox and the recipient's native application channel on October 28. The owning project acknowledged acceptance at 00:25 EDT and reported its completed repair at 02:03 EDT. No hook change or bypass was made here.

The repair is in commit `9c935fb`. Its iterative lexer tracks indented strings, ordinary strings, and nested interpolation. Reported RED controls were four failures out of 95, followed by one nested-interpolation failure out of 96. Reported final validation passed all 96 focused controls, including real disposable commits and both staged/worktree disagreement directions, all 197 host test files, and the sandboxed Nix check.

The independent consumer check passed four cases inside the qualified read-only-host boundary with private Git/HOME state: escaped cache interpolation, unsafe dependency rejection, unsafe staged content with a safe worktree, and safe staged content with an unsafe worktree. The copied installed script's Git blob matched the reported commit before execution. No live repository index or hook configuration was changed. The existing equivalent double-quoted shell string can remain; the shared parser no longer requires that workaround.
