# Prepared test runtime

The shared profiling engine recorded a 13.43-second prepared-runtime lower bound on October 27, 2026. A separate per-suite diagnostic attributed 7.66 seconds to the unit executable and 1.19 seconds to CLI tests. These observations had explicit live-provider exclusions and are diagnostic records, not approved performance baselines.

A syscall trace identified a 5.001-second wait in the filesystem-watcher file-creation test. The polling backend always returns timeout, and the test accepted that result without asserting detection. It also delayed the producer thread by 50 milliseconds. The test now creates and closes the file synchronously after registration. Native backends must still report the event within their bounded wait; polling must immediately report timeout. Initialization failures now fail this test rather than silently returning. The no-change case uses a nonblocking wait.

The rebuilt complete Nix check and fresh host `./test --prepared` passed all available checks: 747 unit cases passed, one optional OS-log case was skipped, and two live-provider suites were excluded. The shared profiler subsequently measured 9.54 seconds for the isolated prepared runtime and 20.90 seconds for the complete prepared invocation. The latter includes Nix evaluation and setup, so it is a mixed phase. No compilation occurred in the isolated runtime. Both measurements remain incomplete because of exclusions; neither establishes compliance with the five-second budget.

A subsequent component diagnostic attributed 3.39 seconds to source-fixture preparation, 2.27 seconds to the unit binary, and 1.14 seconds to CLI tests. Replacing full Git blob staging with an exact intent-to-add path inventory reduced prepared runtime to 6.03 seconds. Its regression first failed because the previous setup dropped force-tracked ignored files from the synthetic inventory. The replacement preserves the exact tracked set, contents, and worktree search, excludes untracked files, and refuses an existing destination.

Two test lanes then overlap the unit binary with the remaining suites. A FIFO-barrier regression first failed on the sequential runner. It now proves actual overlap, waits for both lanes, and checks unit-only, CLI-only, and simultaneous failures without sleeps. Starting the unit lane before the other suites reduced the observed runtime to 4.02 seconds. The complete prepared invocation measured 13.73 seconds including Nix setup/evaluation. All available checks passed, including 747 unit cases and both new harness regressions; exclusions are unchanged. The shared engine correctly labels this observation incomplete/unmeasured rather than a complete budget pass. No performance baseline was approved or changed.

Next, pin the shared profiling adapter and attribute the outer runner's Nix phases separately. Keep safety-enabled correctness checks distinct from optimized measurements. Preserve every required assertion, report exclusions, and retain total queue/setup/result latency. No CPU kernel changed: the measured work removed a sleep and unnecessary Git blob compression, then overlapped independent suites; SIMD work is not indicated.

The subsequent correctness audit found that ReleaseFast disabled the pinned standard allocator's automatic leak checks. Correctness prerequisites now use ReleaseSafe, with an executable runtime-safety control; the shipping CLI stays ReleaseFast. This exposed and led to fixes for an owned metadata leak and C callback-type failures. Both the complete Nix check and fresh host runner now pass 752 unit cases, with one optional unit skip and two live-provider suite exclusions. The shared profiler measured 6.23 seconds for prepared runtime and 47.98 seconds for the mixed complete invocation. This is a distinct profile, remains over the unchanged five-second budget, and is not an approved baseline. The combined profiling job counted both executions, including their repeated exclusions; earlier timings remain ReleaseFast diagnostics.
