The FSEvents backend previously returned success when stream creation returned null or stream start returned false. A separate allocation-failure path lost a copied, NUL-terminated watch path when appending it to the owned list failed. Three persistent fake-framework controls reproduce these defects: two expected typed errors instead find successful void returns, and allocation boundary 1 of 5 retains 11 bytes with no corresponding free. The real aggregate reports 815 passes, one existing skip, three failures, and one allocator-detected leak. Its mandatory transcript verifier blocks the complete Nix check rather than masking that result.

The fixture supplies every framework function through the existing symbol table, counts temporary string/array releases separately, and checks failed-stream stop/invalidate/release exactly once. A scoped thread-local reference provides synchronous mock context; no actual framework, dispatch queue, event delivery, live project, or provider is used. Merely passing the real event callback initially pulled a Mac dispatch symbol into the Linux linker. That setup failure is not a business reproducer. A private borrowed callback parameter resolves the boundary: the production wrapper supplies the original callback, while the fixture rejects unexpected event delivery. The correction retains ownership of each copied path until append succeeds, reports `FSEventStreamCreateFailed` for a null stream, and reports `FSEventStreamStartFailed` for a failed start. Failed start cleans up and clears the stream before returning; subsequent cleanup does not release it twice. Complete Nix checks pass all 818 available unit cases and every available adapter after these three changes, with existing exclusions unchanged.
